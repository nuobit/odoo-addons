Keeps the editable files of each version of a document of the Knowledge
application, such as the Word file its PDF comes from, for the Knowledge
editors.

* The document has a list of editable files, of any kind, in an *Editables* tab
  right after *History*: there they are uploaded, replaced, renamed, sorted and
  removed, as the rest of the document is edited.
* Each version of the document keeps its own files: the list of the document is
  that of the version it shows, and the form of each version has the same
  *Editables* tab.
* A save that changes the content of the document makes a new version, which
  starts with the editable files of the version the document showed; the
  earlier version keeps its own. When the same save also changes the files, the
  new version takes the changes. A duplicated version keeps the files of the
  version it is made from, or, given another document, starts with the files
  that document shows; a duplicated document starts without editable files.
* The editable files of a version change only while the document shows that
  version, so the earlier versions keep theirs as they were. Where
  ``document_page_approval`` is installed, ``document_page_editable_file_approval``
  makes them follow its change requests.
* Only the Knowledge editors, and the managers through them, see those tabs,
  download the files and search by them. A user who edits a document without
  being an editor keeps its files on the new version without seeing them. The
  files are neither attachments of the document nor of the version: the
  chatter does not show them, and a user who cannot read them does not find
  them among the attachments.

Usage
=====

The *Editables* tabs are for the Knowledge editors and managers. A user who only
reads the documents sees neither tab.

To store the editable files of a document, press *Edit* on the document, open
its *Editables* tab, add the files with *Add a line*, replace, rename, sort or
remove them, and save. The content of the document can change in the same save:
the new version then keeps the files as saved, and the earlier version keeps
those it had.

To see the editable files of an earlier version, open the version from the
*History* tab of the document. They can no longer change.

Where ``document_page_approval`` is installed, the editable files follow its
change requests: the usage of ``document_page_editable_file_approval`` says how.

Known issues / Roadmap
======================

* ``document_page_access_group`` limits who reads a document, not who reads its
  versions: a Knowledge editor outside the groups of a document's *Security*
  tab still reads and changes the editable files of its versions.
* Through the API, a write that moves an editable file into a version of another
  company and sets its file in the same call, with ``bin_size`` in its context,
  is not refused: Odoo serves the file from its cache to the check that refuses
  such a move. The screens never send such a call.
* The information inside a file, such as the author, the tracked changes or the
  comments of a Word file, is not cleaned.
* Uninstalling the module deletes every editable file: Odoo deletes the
  attachments of the models it removes.
* Deleting a company deletes its documents, their versions and their editable
  files, but not the attachments that hold the files' contents, as Odoo leaves
  the attachments of whatever the database deletes in a cascade. Such a deletion
  is rare: Odoo refuses to delete a company that other modules' records hold,
  such as the internal project that ``hr_timesheet`` gives each company.
